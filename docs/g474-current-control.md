# Токовый режим G474: J1–J4

Начальная проверка на J4 (104) выполнена 2026-11-02: короткие задания до ±0.2 А.
J1–J3 остаются на CAN-only прошивках, J5–J6 пользователь снял перед тестами.
CAN остаётся 1 Мбит/с nominal, 4 Мбит/с data; настройки Raspberry Pi не менялись.
Результаты и ограничения проверки — в [g474-j4-current-test.md](g474-j4-current-test.md).

## Контур

Внешний энкодер J4 откалиброван по моторному: отдельная таблица выбирается
профилем перед фильтрацией и fusion. Алгоритм и проверка описаны в
[j4-output-encoder-calibration.md](j4-output-encoder-calibration.md).

PWM и регуляторы Id/Iq работают на 16 кГц, период 62.5 мкс. Исправлен прежний
расчёт регуляторов с периодом 50 мкс. Прямое задание `set_current` идёт в Iq
в амперах; Id задан нулём. Позиционные команды Cyphal преобразуются из момента
на выходе редуктора в Iq через Kt и gear_ratio из robot_config.

В подготовленной сборке ограничения находятся в `App/robot_config.h`: Iq ±3 А,
вектор напряжения до 2 В, аварийное отключение при модуле любого фазного тока
выше 22 А. Номинальный ток 3 А, пиковый 22 А и удержание 3 А — предварительные
значения, выбранные пользователем; паспортом мотора они не подтверждены.
`stall_current=3` записан в профиль, однако `detect_stall()` в текущем FOC не
вызывается: повышения тока при остановке нет, удержание также
ограничено рабочим пределом 3 А. Калибровка по-прежнему ограничена ±0.4 А.
Эта сборка прошита на J4 по CAN: предел задания Iq 3 А подтверждён `get_current[17]`; фазная аварийная отсечка задана 22 А. EEPROM-калибровка sequence=5 сохранена.
PI имеет динамическое ограничение напряжения и допускает выход интегратора
из насыщения. При выключенном приводе интегрирование остановлено.

ADC выполняет один четырёхканальный проход на период PWM: напряжение шины,
токи A/B/C. TIM1 CH4 создаёт внутренний TRGO2 на 56.25 мкс. Максимальная
длительность PWM ограничена 53.125 мкс, поэтому перед измерением остаётся
3.125 мкс. При ADC 40 МГц четыре преобразования занимают 1.9 мкс и заканчиваются
до следующего периода. Непрерывный режим и прежнее несинхронное oversampling
16x отключены; сырые значения теперь 12-битные.

Коэффициент датчика 45 мВ/А и делитель напряжения 16 сохранены из прежней
G474 реализации и подтверждены опубликованной схемой VBCores BLDC30A v1.4:
ACS711KEXLT-31AB и делитель 150 кОм / 10 кОм. Измерение датчиками выполнено
непосредственно в фазах. Порядок/полярность и абсолютный масштаб на конкретной
плате ещё требуют аппаратной проверки. Смещения усредняются по 64 измерениям
до включения каскада.
`motor_command_sign` связывает физический Iq с направлением мотора;
`position_direction` применяется только на внешней границе команд и телеметрии.

## Команды

Прошивка стартует разоружённой. `arm 1` включает каскад с нулевым напряжением
и затем задаёт удержание текущей позиции; `arm 0` выключает его.
Для первого теста звено должно быть механически поддержано: ограничение 3 А
не гарантирует удержание веса руки.

Команды только для разрешённого пользователем тестового звена J4:

```sh
y r 104 get_current
y r 104 fault_act
y r 104 arm 1
y r 104 set_current 0.1
y r 104 get_current
y r 104 arm 0
```

`set_current` принимает амперы, ограничивает задание до ±3 А. По таймауту команд
привод переходит на удержание текущего положения, а не выключает питание.
`move` — отдельный диагностический режим до ±2 В через `set_voltage_point`, обходящий PI тока;
аварийная проверка фазного тока остаётся активной.
`set_el_offset` меняет электрический оффсет в RAM только при выключенном приводе.
EEPROM эта прошивка не перезаписывает, старый открытый цикл калибровки отключён.

`get_current` возвращает массив:

| Индексы | Значения |
| --- | --- |
| 0–2 | Ia, Ib, Ic, А |
| 3–5 | Id, Iq, целевой Iq в физической системе dq, А |
| 6–9 | Vd, Vq, напряжение шины, сумма фазных токов |
| 10–13 | raw ADC: шина, A, B, C |
| 14–16 | смещения A/B/C, В |
| 17–20 | лимит тока, тип задания, armed, возраст команды в мс |
| 21–24 | публичный Iq, период контура в секундах, motor_command_sign, код ошибки контура |

Код ошибки контура: 0 — нет, 1 — фазный сверхток, 2 — отсутствует напряжение
шины при включённом приводе. В общем fault manager это бит 16.
После устранения причины используется `set_fault_ack 1`; повторное включение
требует `arm 1`. Ошибка DRV_FAULT также блокирует включение.

Это образ для наладки токового контура: перенос EEPROM нуля/лимитов и полного
сервисного поведения G431 на нижние звенья ещё не завершён. Старый блокирующий
диагностический `set_pos` заменён: теперь принимает выходной угол в радианах,
считает позиционную ошибку по fusion и задаёт момент через контур Id/Iq.
Используются Kp из robot_config и Kd=0, действуют ограничения тока и напряжения.
Траектория пока не формируется; по таймауту команд цель заменяется текущим углом.
Позиционные команды также доступны через штатный
Cyphal subject, но первыми проверяются измерения и малые задания тока.

## Сборки и проверка

Используются существующие каталоги `build/g474-joint1` … `g474-joint4`,
`RUKA3_BOOTSTRAP=OFF`. CAN-образ — `Boards/g474/g474.hex`, полный SWD-образ —
`Boards/g474/g474_full.hex`. Последние CAN-only образы 1/4 сохранены внутри
каждого каталога в `can-only-1m4/` для возврата.

```sh
python3 -m unittest discover -s tests -v
python3 tools/check_can_bundle.py --g474-mode current --manifest build/g474-current-manifest.json
```

Тесты проверяют пересчёт ADC, преобразования abc/dq, допустимое окно измерения,
динамическое ограничение PI и его работу на модели неподвижного RL-мотора.
Они не подтверждают физические коэффициенты датчиков или устойчивость реального
мотора во всём диапазоне; результаты первых коротких аппаратных тестов вынесены
в отдельный отчёт.

## Проверка новой сборки на J4: 3 А / 22 А

Обновление по CAN завершилось `flash_complete`, новые одиночные имена отвечают. Таблица 256 точек, ноль, лимиты и EEPROM sequence=5 пережили обновление. Проверки движения выполнялись только на J4.

Предел ±3 А — ограничитель рассчитанного Iq, а не постоянное задание. В `UNIVERSAL` ток считается из PD-момента и feedforward через `Kt * gear_ratio`; PI тока управляет напряжением. Порог 22 А проверяет измеренные фазные токи. Ток удержания отдельно не задаётся.

Для J4 сейчас `default_position_kp=0.5`, в отличие от J5/J6 с Kp=20. Поэтому при ошибке 0.1 рад позиционная команда требует всего `0.5*0.1/(0.011*36)≈0.126 А` — ограничитель 3 А в таком режиме не достигается.

На малом перемещении через `set_pos`, цель 0.15345 рад, старт 0.10345 рад: положение осталось около 0.102 рад, выборочный пик |Iq|≈0.099 А, фолтов нет. Команда повторялась, поэтому остановка не объясняется истечением командного таймаута. Отдельно после прекращения повторов проверен watchdog: текущий угол стал целью, `cmd_timeout=true`, каскад оставался включён.

Затем через штатный `voltbro.foc.command.1.0`, subject 1124, с Kd=0 переданы временные коэффициенты:

| Kp | Цель, рад | Начало → конец, рад | Выборочный пик Iq, А |
| --- | --- | --- | --- |
| 2 | 0.16398 | 0.10489 → 0.13231 | 0.361 |
| 5 | 0.18398 | 0.13085 → 0.19699 | 0.619 |
| 5 | 0.10398 | 0.19487 → 0.10336 | 1.029 |

На возврате при Kp=5 наблюдалось перерегулирование до 0.06979 рад (~1.96° ниже цели), затем привод вернулся к цели. Это первичная проверка, а не завершённая настройка позиционного контура. Дефолтный Kp не изменялся.

Во всей серии выборочный максимум |Iq target|≈1.092 А, измеренного |Iq|≈1.029 А, измеренной фазы≈1.221 А. Активных/защёлкнутых fault и ошибок CAN нет. В конце `arm=0`, PWM выключен. Сырые логи и стендовый скрипт: `build/g474-joint4/diagnostics/position-3a/`.
