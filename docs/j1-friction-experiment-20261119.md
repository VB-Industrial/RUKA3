# J1: порог трогания и экспериментальная компенсация, 2026-11-19

## Измеренное поведение

Оператор подтвердил отсутствие внешней нагрузки на J1. ROS-контроллеры остановлены. Все испытания этой серии выполняются только на node101. После пробы Kd3 в предыдущей серии персонал отключил питание из-за раскачки. После включения подтверждены arm0, Kp20/Kd0/Ki2 и отсутствие faults; опасная настройка не сохранялась в EEPROM.

В отдельных ограниченных токовых пробах позиционный профиль отключался. Публичный `set_current` менялся ступенями по0.1А, каждый уровень около0.33с. Цикл выполнялся локально на Pi, при смещении около3° возвращал нулевой ток и `set_pos` текущего угла:

| Публичное задание | Смещение за уровень, положительный проход | Смещение за уровень, отрицательный проход |
|---|---:|---:|
|abs0.15А|−0.002°|−0.022°|
|abs0.25А|+0.220°|−0.022°|
|abs0.35А|около0°|−0.044°|
|abs0.45А|+2.575°|+0.022°|
|abs0.55А|+0.545° за0.038с, остановка по углу|−3.208° за0.283с, остановка по углу|

Измеренный Iq в доступных снимках следует заданию. Порог трогания воспроизводится **без позиционного регулятора**. Это доказывает, что проблема не ограничивается настройками Kp/Ki или профилем; не доказывает, что причина только в механическом трении. Остаются внутреннее сопротивление передачи, неравномерность момента/коммутация и оценивание угла.

Отдельная запись `get_pos` во время set_pos показывает изменение относительного смещения моторного и выходного углов до≈0.695°. Моторный угол может быть практически неподвижным, пока выходной энкодер показывает затухающие колебания. Общий runtime перекладывает низкоуровневый снимок: `get_pos[2]` — выходной энкодер, `[3]` — моторный угол в выходных единицах, `[5]` — fused, `[6]` — fused velocity. `[3]` **не** является скоростью мотора. Сравниваются изменения углов относительно начала записи, поскольку абсолютные нули различаются.

Артефакты: `build/set-pos-j1-20261119/{encoders.jsonl,encoders_analysis.py,encoders.png,current_probe.jsonl,current_probe_reverse.jsonl,current_probe.png}`. Вертикальная пунктирная линия current_probe.png — возврат позиционного удержания; участок после неё не является токовым режимом.

## Изменения для проверки гипотезы

В shared `ServiceMotion` добавлена отключаемая знаковая токовая добавка по скорости цели. Она не изменяет q/v-профиль и не интегрирует ошибку:

```
x = clamp(v_ref / 0.005 рад/с, -1, 1)
I_friction = friction_i * x * (1.5 - 0.5*x*x)
```

Добавка переводится в момент через существующий Kt×gear и применяется рядом с интегральной компенсацией нагрузки. При v_ref=0 равна0. На hard/soft границах действует существующее ограничение наружного воздействия. Дефолт friction_i=0, сохранения в EEPROM нет. Допустимый диапазон0…min(1А, holding_current_limit). Это экспериментальный способ проверить влияние порога, не утверждение об окончательной модели трения.

Регистры Register Access, отдельно на каждом узле:

- `friction_i`: REAL32, read/write, амперы публичного направления, амплитуда компенсации;
- `i_friction`: REAL32, read-only, рассчитанная знаковая добавка до масштабирования у границы;
- `pos_v`: REAL32, read/write, vmax существующего set_pos-профиля, рад/с;
- `pos_a`: REAL32, read/write, amax существующего set_pos-профиля, рад/с².

pos_v/pos_a по умолчанию равны старым настройкам0.5/1. Значения должны быть положительными и не выше этих штатных пределов. Изменения действуют со следующего set_pos: ускорение активного профиля зафиксировано при его создании. Командный и feedback wire-контракт не менялся; второй планировщик не добавлен. Установка коэффициентов Kp/Kd/Ki и i_limit не меняет friction_i.

## Развёртывание

Первый образ только приложения J1: SHA256 `bd6c76338d69d0f6ba8d3d74c44f26793cba43802ed8ca97652e1bfd0975d650`. FOC trace отключён. CAN загрузка завершена flash_complete, CRC32 D9045810; калибровка/limits и первые4 поля eeprom_diag сверены с исходными, EEPROM sequence не изменён. Bootloader не записывался. Другие оси не обновлялись.

Первый заход не дошёл до передачи образа: запрос входа в bootloader не был принят. Приложение продолжало отвечать с прежними RAM gains и arm0. Повтор с отдельным Cyphal node-id прошёл; при короткоживущих RPC-клиентах следует учитывать переиспользование transfer-ID и окно дедупликации.

Второй образ добавляет ограниченные pos_v/pos_a: SHA256 `2f826aac9ce1560b17d8b835a4147207278de3cc60bf23ed88a7b0ba42166d6a`. Результат его загрузки и медленных проходов записывается отдельно в `flash-slow.log`, `after-slow-flash.jsonl`, `slow*.jsonl`.

Локальный испытательный скрипт `guarded_trial.py` запускается nohup на Pi: ограниченное время, faults/потеря feedback и контроль колебаний после завершения профиля. При ошибке отключает friction_i и возвращает20/0/2. Доступность SSH не нужна для этого отката. Скрипт не отключает PWM, чтобы не снимать удержание.
