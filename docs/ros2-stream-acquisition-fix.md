# Ослабление удержания J5 при потоке ROS: 2026-11-12

Повтор после исправления ROS gains: новая библиотека прочитала Kp30 для J1–J5 и Kp5 для J6, в CAN фактически передаётся Kp30 на J5. Ошибка PATH_TOLERANCE_VIOLATED повторилась: индекс4 = joint_5, ошибка−0.162985рад. Привод оставался включённым, fault-флаги0; после остановки измерены цельJ5≈0.310056рад, угол≈0.422782рад, токIq≈−0.327А, Ki0.

Снят сохранённый план MoveIt. Пользователь действительно задавал поворот J1:

- J1: −0.00344944→−0.21690028рад.
- J5: 0.14707041→0.14718234рад (изменение всего0.00011194рад).

Таким образом, J5 планировалась практически неподвижной. При этом её потоковые setpoints всё же слегка меняются вследствие интерполяции/планирования.

## Подтверждённый программный дефект

`ServiceMotion::servo` сравнивал каждую новую цель с измеренным углом. При ошибке более0.1рад вызывал `position(target, current, ...)`, заново ставя начало профиля в измеренный угол. В обновляющемся ROS-потоке это повторяется на каждом пакете: профиль не разгоняется, его ошибка в начальной точке близка к0, и пропадает P-составляющая удержания.

Регрессионный тест с нагруженной/отстающей осью и маленькими приращениями цели воспроизводит дефект: до исправления assertion падает, после проходит. Исправление: первая дальняя цель и новые большие скачки по-прежнему включают плавный захват; небольшие последовательные приращения потоковой цели передаются в позиционный регулятор напрямую, поскольку ROS уже формирует профиль. Повторы той же дальней цели не сбрасывают захват. Сервисный `set_pos`, пределы тока, лимиты и watchdog не меняются.

Все18host-тестов прошли. Образы требуют отдельного применения; без перепрошивки работающий привод продолжает использовать прежний алгоритм. Проверочный физический манёвр автоматически не запускался.

## Что ещё требует аппаратной проверки

Сама по себе P-регуляция при Ki0 допускает статическую просадку под нагрузкой. После исправления потока нужно отдельно оценить удержание и компенсацию нагрузки J5; увеличение допусков JTC не является исправлением. Не утверждается, что одна программная правка уже подтверждена физическим испытанием.

## Применение на J5

После подтверждения пользователем поддержки руки остановлены ROS-контроллеры и разоружена J5. По CAN записано только приложение node105: 102695 байт с дополнением до47, CRC32 `0x99860A70`, подтверждение каждого блока, результат `flash_complete`. Загрузчик не перезаписывался.

После старта подтверждены arm0, отсутствие active/latched fault, can_err0 и валидная калибровка. `cal_data`, hard/soft-лимиты и выбранный EEPROM-слот/sequence совпали со снимком до обновления. В RAM восстановлены пользовательские Kp30, Kd0, Ki0, i_limit2. EEPROM не записывалась. Остальные пять приводов не прошивались.

ROS не перезапускался; движение с новой прошивкой автоматически не выполнялось. Логи: `build/ros2-diagnostic/j5-stream-update/`, на Pi — `~/ws_ruka3/ruka3-stream-fix-20261112/j5-*`.
