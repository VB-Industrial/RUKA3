# G474 FOC: изолированная диагностическая запись

Основание и программа A–D: [статический аудит](g474-foc-static-audit.md). Регулятор, PWM limits, ADC timing, CAN, EEPROM и моторные команды не менялись. Физические испытания описаны в отдельных отчётах J3/J4. Регистратор сам не задаёт моторных целей; добавленный 2026-11-19 `trace_d_pulse` — отдельная явно вызываемая диагностическая функция воздействия.

## Сборка

По умолчанию `RUKA3_FOC_TRACE=OFF`: нет регистратора, hooks и диагностических регистров. Для полной G474-сборки в существующей папке нужного звена:

```sh
cmake -S . -B build/g474-joint3 -DRUKA3_FOC_TRACE=ON
cmake --build build/g474-joint3 -j4
```

`RUKA3_FOC_TRACE_FRAMES=256` (1…256), `RUKA3_FOC_TRACE_DECIMATION=1` (1…1024). Bootstrap несовместим с регистратором. G431 не инструментирована.

256 кадров ×128 байт =32 КиБ RAM. Полная частота —16 кГц, окно16 мс, спектральный шаг62.5 Гц: оно не разрешает механические колебания в единицы Гц. Decimation увеличивает окно, но дополнительного anti-alias фильтра нет. Нельзя интерпретировать высокочастотный пик после decimation без проверки алиасинга. Для низкочастотной механики нужен отдельный длинный лог.

Диагностика вносит overhead. ISR body включает обработчик HAL и регистратор, но исключает exception entry/exit, пролог и несколько завершающих инструкций измерителя. Это измерение длительности, а не доказанный WCET. При зависании ISR capture не завершится.

## Управление записью

Существующий `uavcan.register.Access` используется только для новых регистров. Основной Cyphal wire-контракт не меняется. `tools/foc_trace.py` требует настроенных переменных PyCyphal, локального node-id и DSDL как у действующего CAN-инструментария; моторные команды скрипт не отправляет.

- `foc_trace`: 1/2/3 — конечная запись measurement/control/angle; 4/5/6 — те же профили в кольцо; 0 — остановить/заморозить; −1 — очистить замороженную запись. Новая запись во время активной отклоняется. Чтение возвращает активный профиль либо0, полное состояние — в `trace_info`.
- `trace_info`: INTEGER32[32], метаданные ниже.
- `trace_page`: индекс замороженного кадра, от0; чтение только после заморозки.
- `trace_data`: INTEGER32[32], точные биты кадра. Знаковые слова переводятся в uint32; float32 декодируется по битам, без потери ADC/Q31/таймера в float.

```sh
# Только после отдельного согласования испытания и диагностической прошивки:
python3 tools/foc_trace.py arm --node 103 --profile measurement
python3 tools/foc_trace.py dump --node 103 --output build/foc-audit/B-measurement.json
python3 tools/foc_trace.py analyze build/foc-audit/B-measurement.json \
  --compare build/foc-audit/C-measurement.json --output build/foc-audit/comparison
```

`arm` здесь запускает **регистратор**, не силовой каскад. Для кольца добавить `--ring`, затем явно вызвать `stop --node 103`. `dump` не запускает/останавливает запись автоматически и проверяет неизменность capture-id после выгрузки. Три профиля — отдельные окна: нельзя склеивать их как синхронные сигналы одного периода.

## Формат schema1

Общие слова0…11:

| Индекс | Смысл |
|---|---|
|0…4|Номер периода, DWT CYCCNT входа, интервал входов, длительность body, максимум body|
|5|TIM1 CNT входа|
|6…9|DMA NDTR до/после чтений, ADC ISR, DMA ISR|
|10|Flags|
|11|DWT offset начала чтений ADC от входа ISR|

Payload12…31 перечислен с именами и типами в `FIELDS` файла [foc_trace.py](../tools/foc_trace.py). Measurement содержит точные raw ADC, фазные токи/сумму, dq до/после LPF, offsets, bus, предыдущие PWM, motor raw/electrical angle. Control содержит native Iq до/после ограничений, Id target, ошибки/измерения dq, PI до clamp/после clamp, применённые Vdq, лимиты, интегралы и staged PWM. Angle содержит motor raw, угол после offset/LUT, прогноз/коррекцию/скорость/ускорение наблюдателя, innovation, предыдущий прогноз, T, оригинальные CORDIC Q31, CPR/pole pairs/offset/LUT и gains. Контрольный Iq относится к native q axis после `current_direction`, не к публичному направлению звена. PI raw — кандидат до clamp с пробным шагом интегратора; сохранённый интеграл после anti-windup может отличаться. Единица интеграла —А·с, напряжение интегрального вклада =Ki×integral.

В VOLTAGE неисполнявшиеся PI/targets/errors равны NaN, `current_loop_ran=0`. Это устраняет неоднозначность старого `get_current[5]`. Observer-поля валидны при флаге16; первый шаг инициализации не выдаётся за измеренный прогноз. Разность прогноза с raw — ошибка относительно измеренного энкодера, **не** независимая ошибка электрического нуля.

Flags: bit0 software PWM entry; bits1…3 mode; 4/5 d/q saturation; 6 vector limit; 7 PWM cap; 8 NDTR изменился; 9 ADC OVR; 10 DMA TE; 11 update pending в конце; 12 interval>1.5T; 13 current PI выполнен; 14 CORDIC INT32_MIN; 15 hardware MOE в конце; 16 observer обновлён. Нормальное постоянное NDTR **не доказывает** целостность: полный оборот circular DMA возвращает NDTR к прежнему значению. Флаги только наблюдаются, не очищаются.

Packed PWM: младшие16бит=A, старшие16=B; следующее слово —C в младших16 и для measurement TIM1 CNT начала чтений в старших16. Duty=CCR/(ARR+1). Previous PWM соответствует ADC предыдущего периода при нормальном расписании, staged —следующему update. При пропусках/пересечении CCR writes с update такое сопоставление недостоверно; флаги помогают обнаружить нарушение дедлайна, но не восстанавливают историю shadow-регистров.

Метаданные `trace_info`:

| Индекс | Смысл |
|---|---|
|0…6|magic0x46544331, schema1, state(0idle/1active/2frozen), profile, count, capacity, words32|
|7…10|Глобальный period, CPU Hz, expected cycles/T, decimation|
|11…17|Late entries, pending updates, sampled DMA changes, OVR observations, TE observations, max body cycles, max interval|
|18…23|Выбранная страница, capture-id, pole pairs, TIM PSC/ARR/CCR4|
|24…27|ADC common CCR, ADC CFGR/SMPR1, DMA CCR|
|28…31|Биты float LPFalpha, биты float observer g3, joint-index, DWT CTRL|

OVR/TE могут быть sticky; счётчики показывают число **наблюдений**, не число независимых аппаратных ошибок. UIF не считает несколько пропущенных периодов. Cycle delta обрабатывает один uint32 wrap; длительные остановки отладчиком нарушают временную интерпретацию.

Анализатор строит осциллограммы, PWM/raw ADC/интегралы, электрическую разность прогноза, спектры и таблицу `metrics.json`. На нерегулярной сетке FFT подавляется. Спектры разных физических единиц подписаны; пики Vq и тока не сравниваются по численному масштабу. Дополнительно `python3 tools/audit_foc_math.py` воспроизводит полюса наблюдателя и частотные свойства LPF без подключения к устройству.

Ни host-тесты, ни синтетические графики не подтверждают устойчивость настоящего привода. Реальная запись A–D остаётся следующим отдельным этапом.


## Импульс по оси d (добавлен 2026-11-19)

Только trace-сборка G474 предоставляет REAL32-регистр `trace_d_pulse`. Это **воздействие на мотор**, в отличие от запуска обычной записи. Выполнять только на согласованном с оператором звене.

Запись ненулевого значения в диапазоне ±0.12В запускает: 64 периода Vd/Vq0, 64 периода Vd=значение/Vq0, затем128 периодов Vd/Vq0. При16кГц номинальная длительность импульса4мс, всего записи16мс. MCU считает периоды FOC, CAN нужен только для запуска и последующей выгрузки. Фактические edges следует проверять по сохранённым PWM и late/pending flags.

Предусловия: arm1, нет latched fault, нормальное управление разрешено, активен `move 0`, нет другой записи/импульса, размер кольца256 и decimation1. При неподходящем режиме запрос отклоняется. При отключении PWM или смене setpoint type/ненулевой voltage target импульс отменяется. Тест не восстанавливает старую позиционную цель и не меняет EEPROM/gains. После нормального окончания остаётся исходный режим `move 0`; перевод обратно в hold выполняет оператор/испытательный скрипт.

Ноль отменяет импульс и замораживает запись. Чтение возвращает напряжение активного теста либо0. Другие команды управления записью во время этого теста отклоняются. Flags bit17=окно импульсного теста, bit18=ненулевой staged Vd. Последний флаг относится к рассчитываемому PWM, а сохранённые previous PWM —к предыдущему измерительному периоду; поэтому edges смещены относительно друг друга.

Нижние/верхние сервисные лимиты позиционирования не используются для вектора Vd. Малый Vd не гарантирует отсутствие момента при неверной электрической ориентации; проверять raw motor encoder. Звено для испытания и условия остановки согласуются отдельно. На J4 выполнены только±0.06/±0.12В, по4мс; результаты —[отчёт J4](g474-foc-j4-rl-20261119.md).
