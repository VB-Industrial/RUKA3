# Имена регистров G431/G474

Эта схема имён прошита на J4/J5/J6 (nodes 104–106); для J1–J3 пока только собрана. Каталог и обработчики общие для обеих плат; состояние перехода — в `g431-g474-sync.md`.

Первые 23 регистра совпадают с RUKA2, кроме пары `pos_set` / `pos_get`, которая по решению пользователя называется `set_pos` / `get_pos`. Одиночные команды и диагностика сохраняют привычные имена. Дополнительная пара тока — `set_current` / `get_current`; остальные дополнительные регистры тоже без одиночных префиксов.

Исторические `tmc_pos_set` и `tmc_diag` оставлены для совместимости привычных команд. В этой прошивке они работают с нормализованной моторной координатой BLDC и диагностикой его драйвера соответственно. `move` принимает вольты. `zero_set` вызывается без аргумента. `arm` принимает 0/1, возвращает int32[5]. Алиасы старых имён не добавлялись.

На J4 уже используются новые имена (`man_cal`, `arm` и т.д.). EEPROM-калибровка при обновлении сохранилась, sequence=5.

## Коэффициенты позиционного управления

`kp` и `kd` — REAL32, чтение/запись, неотрицательные конечные значения. Хранятся в RAM; после reset берутся из `robot_config` (J1–J6: 5/0). Применяются сразу к `set_pos` и удержанию, не перезапуская траекторию. `active_gains` — read-only REAL32[2], фактически применяемые `[Kp, Kd]`.

```sh
y r 104 kp 5
y r 104 kd 0
y r 104 set_pos 0.5
y r 104 active_gains
```

Cyphal-поток использует трапецию для новых целей дальше 0.1 рад и прямое управление для близких целей. Обе платы используют `angle_kp`/`velocity_kp` пакета `voltbro.foc.command.1.0`, subjects 1121–1126 из robot_config. Kp/Kd заданы в общей шкале выходного момента; Оба адаптера делят их на gear_ratio для нативного моторного масштаба; Kp измеряется в Н·м/рад выхода, Kd — в Н·м·с/рад выхода. Изменение регистров не подменяет коэффициенты пакета. Старые G431 MIT/SpecificControl сняты; см. состояние обновления в `g431-g474-sync.md`. Это позиционные коэффициенты, не PI-регулятор тока.

## Компенсация постоянной нагрузки

| Регистр | Тип | Назначение |
| --- | --- | --- |
| `ki` | REAL32, чтение/запись | Коэффициент интегратора, А/(рад·с); по умолчанию 0 |
| `i_limit` | REAL32, чтение/запись | Предел модуля накопленной добавки, А |
| `i_current` | REAL32, чтение | Накопленная добавка Iq в публичном направлении звена, А |

`i_limit` при старте задаётся `robot_config.command.default_integral_current_limit_a`, с ограничением min(stall_current, nominal_current): J1–J3 3 А, J4 1 А, J5–J6 2 А. Во время наладки J4 допускает увеличение до 3 А; значения выше физического предела, отрицательные/нечисловые значения отвергаются. Общие ограничения тока и момента мотора сохраняются. `ki=0` отключает компенсацию и обнуляет добавку; уменьшение `i_limit` немедленно ограничивает накопленное значение. Все настройки в RAM, после reset восстанавливаются начальные значения.

При неподвижной заданной цели добавка накапливается как `Iq_I += ki * error_rad * dt_s` и остаётся при нулевой ошибке. Подстройка работает при hold, завершённой трапеции `set_pos` и прямом Cyphal-потоке с нулевой заданной скоростью. Во время трапеции/ненулевой заданной скорости накопленная компенсация сохраняется без дальнейшего интегрирования. Это условие заданной скорости, а не детектор физической остановки.

`arm 0`, fault с отменой движения, прямые `move`/`set_current` сбрасывают накопление. Новый позиционный target, замена Cyphal-пакета и watchdog hold сохраняют его. Для ручного сброса достаточно `ki=0`. Коэффициент Ki общий, packet Kp/Kd не меняются, DSDL не менялся.

На насыщении общего запроса тока интегратор не увеличивает насыщение; обратное изменение допускается. В hard-limit накопленный наружный ток удаляется, в soft-зоне его выход ограничивается существующей политикой прямого тока. `i_current` показывает внутреннее накопление до ограничения выхода в soft-зоне. Напряжение/нагрев остаются ограничениями реального привода: достигнуть заданного тока удаётся не при всех скоростях и напряжениях.

Новая функция собрана для J1–J6, проверена host-тестами и моделью постоянной нагрузки. J4 прошит по CAN: чтение/запись Ki при arm=0 и возврат Ki=0 после reset проверены, EEPROM sequence=5 сохранилась, fault/CAN errors=0. Финальное состояние arm=0, Ki=0; нагруженное испытание не выполнялось. Логи: `build/g474-joint4/diagnostics/integral-smoke/`.

## encoder_diag: оба энкодера и моторный наблюдатель

REAL32[12], чтение через `y r 105 encoder_diag`. Поля6/7/8/11 добавлены
без изменения длины регистра и остальных полей:

| Индекс | Значение |
|---:|---|
|0|Сырой внешний энкодер, тики|
|1|Внешняя координата после LUT относительно нуля, тики; NaN вне применимой калибровки|
|2|Внешний угол, рад|
|3|Моторная оценка выходной скорости, публичный знак, рад/с|
|4|Скорость внешнего энкодера, публичный знак, рад/с|
|5|Максимальный скачок внешних тиков за сессию|
|6|Моторные тики драйвера энкодера, до электрического оффсета/LUT|
|7|Скорректированный роторный угол до моторного наблюдателя, рад; до умножения на число пар полюсов|
|8|Электрический угол после моторного наблюдателя, рад|
|9|Ожидаемый люфт, рад|
|10|Ошибка предсказания верхнего наблюдателя, рад|
|11|CPR моторного энкодера из драйвера|

Поля6/7/8/11 читаются вместе при кратком запрете прерываний. Остальные поля
и отдельные запросы get_pos/get_current не являются одновременными с ними.
Моторные тики уже учитывают направление, заданное драйвером энкодера; это не
необработанное SPI-слово с битами паритета/ошибки. Поля7/8 в нативной СК мотора,
без публичной position_direction. Чтение не меняет FOC, оффсет, LUT или EEPROM.
