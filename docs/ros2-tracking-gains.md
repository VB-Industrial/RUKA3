# Удержание при короткой команде J1: 2026-11-12

JointTrajectoryController прервал цель с `PATH_TOLERANCE_VIOLATED`: индекс `joint 4` соответствует `joint_5`, поскольку индексация в tolerances.hpp начинается с нуля. Команда пользователя была небольшим поворотом J1; ошибка возникла на оси удержания.

Пассивно сняты данные работающей руки, без новых целей и изменений коэффициентов:

- В регистрах nodes101/103/105: Kp=30, Kd=0, Ki=0.
- В CAN-командах subjects1121/1123/1125 от ROS: Kp=5, Kd=0, около100команд/с.
- J5 после прерывания: цель0.764018рад, положение около0.998рад, ошибка около−0.234рад. Fault-флаги отсутствуют.

Обнаружен дефект интеграции: ROS постоянно передавал зафиксированный общий Kp=5 и тем самым ослаблял заданную пользователем жёсткость. Исправление: при активации прочитать `kp`/`kd` каждого привода и использовать эти значения в обычном потоке, при старте с нулевой целью и при удержании. Настройки прошивки и допуски JTC не меняются.

Виртуальный CAN-тест использует разные Kp/Kd для шести нод и проверяет их в фактически отправленных пакетах. Проверены также нулевые цели, восстановление из soft-зоны, отмена траектории и остановка при потере feedback. Аппаратная проверка движения после исправления требует нового запуска пользователя; автоматически работающий controller manager не перезапускается.

Исправление устраняет подтверждённую подмену gains. Не является подтверждением окончательной настройки удержания под нагрузкой: остаточную ошибку и необходимость Ki следует оценивать после проверки с заданными коэффициентами.

ARM64 Release собран в `~/ws_ruka3/build-gains`, библиотека установлена атомарной заменой в обычный `build/ruka3_control`. Работающий процесс сохраняет прежнюю загруженную библиотеку; сам не перезапускался. Новый driver будет загружен при следующем запуске `with_cont`. Резервная копия: `~/ws_ruka3/backups/libruka3_control.before-firmware-gains.so`.
