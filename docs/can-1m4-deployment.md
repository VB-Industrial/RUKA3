# Переход на CAN-FD 1/4: выполненные действия

Дата: 2026-10-30, Europe/Moscow.

Все шесть приложений обновлены по CAN на старой скорости 1/8.
После каждого звена пользователь последовательно отключал его питание;
повторное включение всей руки предусмотрено после переключения Raspberry.
Raspberry переключена, пользователь включил всю руку. Ноды 101–106
подтверждены чтением `get_node_id` на 1/4. Моторы на новой скорости
ещё не армировались.

| Звено | CAN ID загрузки | Новый ID приложения | Передано байт с padding | CRC32, подтверждённый VBBoot |
| --- | --- | --- | --- | --- |
| J6 | 106 | 106 | 84177 | `2F8EB556` |
| J5 | 4 | 105 | 80699 | `9CA0D5FA` |
| J4 | 104 | 104 | 36989 | `9A5977F4` |
| J3 | 103 | 103 | 36989 | `DD42D272` |
| J2 | 102 | 102 | 36989 | `FDD4220D` |
| J1 | 101 | 101 | 36989 | `9C6F328C` |

J6 потребовала повторного включения питания после неудачной попытки
передачи с ACK каждого блока. Все окончательные успешные заливки выполнены
потоковым режимом VBBoot с блоками 47 байт и паузой 5 мс.
Каждый окончательный запуск uploader завершился `flash_complete` после
подтверждения команды DONE. На J5 первоначально была VBDrive 5.0.0 с node ID 4;
пользователь подтвердил соответствие этого ID физическому J5 перед записью.

J1–J4 — CAN-only bootstrap, J5–J6 — моторное приложение. Загрузчики при этой
CAN-заливке не заменялись. Полные SWD-образы 1/4 только подготовлены локально.
Ограничения старых загрузчиков и восстановления описаны в документе подготовки.

На Raspberry установлен `/opt/ruka3/can_profile.py` и override
`/etc/systemd/system/canstarter.service.d/10-ruka3-can.conf`.
Сервис `canstarter.service` перезапущен и завершился с `ExecMainStatus=0`.
`can0` и `can1` проверены скриптом `--check`: 1 Мбит/с nominal (SP 75%,
SJW 25 нс), 4 Мбит/с data (SP 80%, SJW 50 нс), нормальный ISO CAN-FD,
error reporting, restart-ms=1000, txqueuelen=65535.
Профиль сохраняется после перезапуска Raspberry. Ethernet/Wi-Fi и состав
интерфейсов Yakut не изменялись.

После включения руки профиль сохранился, обе CAN-линии в ERROR-ACTIVE.
Счётчики can0 bus-errors/RX-errors/TX-errors равны 0: ни в контрольном
интервале 5 секунд, ни после чтения регистров всех шести нод роста не было.

J5: `get_joint_state=1`, `get_calib_valid=false`, `get_fault_act=8`.
J6: `get_joint_state=3`, `get_calib_valid=true`, `get_fault_act=0`.
Это состояние было зафиксировано до моторной калибровки J5.

По последующей команде пользователя выполнена `set_motor_calib 1` на J5.
После процедуры и штатного перезапуска: `get_calib_valid=true`,
`get_joint_state=3`, `get_fault_act=0`, `get_calib_inv=false`,
моторный calibration offset = -298. Ошибки CAN остались на нуле.
Команды изменения нуля/лимитов и arm при этой проверке не выполнялись.
Пользователь отметил начальное движение примерно на 90 градусов;
начальный поиск нуля энкодера в текущей калибровке требует отдельной проверки.
