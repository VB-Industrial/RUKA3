# J4: проверка рассчитанного PI только по оси d, 2026-11-19

Продолжение [идентификации по Vd](g474-foc-j4-rl-20261119.md). Оператор разрешил продолжение; J4 свободен, J5/J6 отключены. Испытывался только node104, без позиционных проходов. Показание БП подтверждено оператором: ровно24В, telem≈23.8В.

## Изменение

Во временном диагностическом приложении изменён только второй PIDConfig конструктора FOC, соответствующий d_reg:

- d: Kp0.035, Ki75, Kd0;
- q: исходные Kp2, Ki600, Kd0;
- T62.5мкс, current LPFalpha0.0925, voltage/current limits, энкодер, наблюдатель, EEPROM/CAN —прежние.

Это отправная точка≈100Гц по эффективной d-модели, не окончательная настройка всех токовых осей. Позиционные gains не подбирались: после старта штатные defaults5/0/0, arm захватывает текущую позу. Коэффициенты не записывались в EEPROM.

Приложение собралось в существующей папке `build/g474-joint4`, сохранено только в `diagnostics/foc-trace/pid-d-100hz/` вместе с `parameters.json`. SHA256 HEX `16b38c0b399f0492c313a3c526dc30bbd177950c15ed61ea184b25444f4aeb5f`. Записано по CAN, затем после измерений по CAN восстановлено исходное диагностическое приложение SHA256 `6ccadf71f5922f9aca68f2322a5c4012e712cd2d73c3823d3a5137b61211d3fb`. Bootloader/EEPROM не переписывались.

Временная правка `Boards/g474/App/motor.cpp` восстановлена с проверкой отсутствия конкурентных изменений; постоянных изменений motor.cpp/robot_config нет. Каноническая сборка снова traceOFF и успешно собрана. Программный алгоритм регулятора в этом опыте не менялся.

## Измерения

Контрольное состояние —удержание текущей позы при малом Iq target. Отдельные16мс окна256samples при16кГц; measurement/control не синхронны между собой, их нельзя склеить в один общий период.

| Сигнал, STD в А | До: d2/600, q2/600 | После: d0.035/75, q2/600 |
|---|---:|---:|
|Id raw|0.15294|0.02987|
|Id filtered|0.03089|0.00781|
|Iq raw|0.08648|0.08214|
|Iq filtered|0.01864|0.01963|

Фон VOLTAGE0 из предыдущего опыта: STD Id raw0.02332А. Таким образом, изменение d-регулятора снизило колебания Id примерно в5.1раза, близко к измерительному фону, но q-колебания почти не изменились.

В разных control-окнах STD Vd снизилось0.05699→0.000471В. Vq0.04294→0.03091В; из-за коротких разных окон это не считается точной долгосрочной оценкой улучшения q-регулирования. В measurement до изменения сильный пик около1187.5Гц в dq; после изменения сохраняется заметный q-пик около1062.5Гц. FFT resolution62.5Гц.

Роторные средние raw6238.82→6238.54ticks, electrical angle0.03509→0.03386рад; сравнение проведено примерно в одной моторной фазе, не в существенно разных положениях. Шум raw encoder1.59→1.41ticks, наблюдатель/его настройки не менялись. Разница режимов не объясняется увеличением позиционного Kp —он не увеличивался.

Наличие нужных коэффициентов подтверждено данными самого регулятора: least-squares `V_pi_raw=Kp*error + Ki*integral_as` даёт:

- baseline d≈2/600, q≈2/600;
- trial d≈0.035/75, q≈2/600.

Остаток соответствия формуле порядка10⁻⁹В и меньше, нет насыщения/clipping. Это проверка применённых коэффициентов, не независимая идентификация двигателя.

Late/pending/NDTR-change/ADC OVR/DMA TE в записанных окнах0; max ISR body≈53.9мкс приT62.5мкс. Fault_act0. Как и прежде, отсутствие флагов не доказывает полный WCET/DMA coherence.

## Вывод и границы

Изолированная замена только токового PI_d подавляет d-колебания; прежний q-регулятор остаётся шумным. Это дополнительное прямое свидетельство роли настройки токовой обратной связи, а не только моторного энкодера или внешнего позиционного профиля.

Однако опыт проводился около нулевого задания: нельзя считать подтверждённой отработку ненулевого Id, достаточное быстродействие, параметры q-axis или работу под нагрузкой. Новые коэффициенты пока не приняты постоянными. Следующий этап —отдельно проверить переходный процесс рассчитанного PI_d и идентифицировать/проверить q-регулятор; при свободном роторе q-идентификация должна учитывать вращение/противо-ЭДС. Подставлять d-модель в обе оси без проверки не следует.
